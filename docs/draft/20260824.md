# 普通の多対多 vs 自己参照型の多対多(TraceNote)

## 概要

なぜ、`belongsToMany()`でなく、`hasMany`と`belongsTo`にしたのか

## 普通の多対多

`User <-> Role`: 一般的な多対多。

1人のUserが複数のRoleを持ち、1つのRoleを複数のUserが持てる。

- users
- roles
- role_users (中間テーブル)

```
users

id | name
---|------
1  | John
2  | Alice

roles

id | name
---|------
1  | admin
2  | editor

role_user

user_id | role_id
--------|--------
1       | 1
1       | 2
2       | 2
```

> $user->roles を実行すると、何が取得される？
> UserとRoleの間にはどんな関係がある？

`$user->roles`の最終的な結果は、RoleモデルのCollection。

中間テーブルの2行そのものを取得しているわけではない。

中間テーブルを利用しているけど、ユーザーが最終的に受け取るのはRole。

## TraceNoteの場合

TraceNoteでは、`Trace <-> Trace`という関係を作っている。

```
Trace #10 [Laravel]
    |
    | related
    |
Trace #20 [Eloquent]
```

DBでは:

```
trace_relations

id | from_trace_id | to_trace_id | relation_type
---|---------------|-------------|--------------
1  | 10            | 20          | related
```

> 普通の多対多 User <-> Role と比較して、TraceNoteでは何が特殊？

Traceモデルが、自分自身であるTraceモデルを参照している。

## 中間テーブルを見比べる

普通の多対多:

```
role_user

user_id
role_id
```

TraceNote:

```
trace_relations

from_trace_id
to_trace_id
relation_type
```

> なぜ、trace_id x2でなく、from_trace_id to_trace_idなのか？

そのtrace起点(from)関連なのか、そのtraceに対する(to)関連なのかを明確にするため。

=> そのtraceに向かってくる矢印(to)とそのtraceから出ていく矢印(from)

```
Trace A -- from --> TraceRelation -- to --> Trace B
```

## 自己参照

普通の多対多なら、`$user->roles`とすると、`User -> 中間テーブル -> Role`と辿ることができる。

TraceNoteでは、`$trace->outgoingRelations`から`$relation->toTrace`と辿ることで、

`Trace -> TraceRelation -> Trace`となる。

> TraceNoteの自己参照型の多対多とは、具体的にどうゆう意味？

TraceがTrace同士と多対多で単純に関連するのに加え、それぞれの関連に意味を持っている。

Trace同士がお互いに関連しているというだけでなく、その関係が前提知識・子知識・関連知識なのかという情報も必要。

## TraceRelationモデル

ここまでを考えた上で、なぜTraceNoteでは単純な`belongsToMany()`だけでなく、

`TraceRelation`というモデルを作ったのか？

中間テーブル自体に「関連の情報」を持たせ、それを1つのEloquentモデルとして扱いたかったため。

TraceAとTraceBの間にどうゆう関係があるのかという関係そのものを1つのオブジェクトとして扱える。

TraceRelationモデルを作ったから、その中でfrom側のTraceとto側のTraceへのリレーションも定義できる。

## Trace側: belongsToMany()でなく、hasMany()

TraceNoteでは、Trace 同士を trace_relations テーブルを介して多対多に関連付けている。これは同じ Trace モデル同士を関連付けるため、自己参照型の多対多である。

trace_relations では、どのTraceとどのTraceが関連しているのかを表現するため、from_trace_id と to_trace_id を持たせている。

from_trace_id は矢印の出発点となるTrace、to_trace_id は矢印の到着点となるTraceを表現する。

また、Trace同士の関連には「前提知識」「子知識」「関連知識」などの意味があるため、relation_type によって関連の種類も保持している。

さらに、trace_relations の1行1行が「2つのTraceがどのような関係にあるか」という意味を持つため、その1行をEloquentのオブジェクトとして扱えるように TraceRelation モデルを定義している。

Trace から関連する TraceRelation を取得する場合、1つのTraceに複数の関連レコードが存在し得るため、Trace → TraceRelation は hasMany で定義している。

その際、from_trace_id を基準にする outgoingRelations() と、to_trace_id を基準にする incomingRelations() の2つを定義することで、自分から出ていく関係と、自分に向かってくる関係の両方を取得できる。
