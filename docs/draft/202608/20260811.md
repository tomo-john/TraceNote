# Policy

## 概要

このユーザーはこのモデルに対して、この操作をしてもいいか？を判断する場所。

## app/Policies/TracePolicy.php

```php
<?php

namespace App\Policies;

use App\Models\Trace;
use App\Models\User;
use Illuminate\Auth\Access\Response;

class TracePolicy
{
    public function viewAny(User $user): bool
    {
        return false;
    }

    public function view(User $user, Trace $trace): bool
    {
        return $user->id === $trace->user_id;
    }

    public function create(User $user): bool
    {
        return false;
    }

    public function update(User $user, Trace $trace): bool
    {
        return $user->id === $trace->user_id;
    }

    public function delete(User $user, Trace $trace): bool
    {
        return $user->id === $trace->user_id;
    }

    public function restore(User $user, Trace $trace): bool
    {
        return false;
    }

    public function forceDelete(User $user, Trace $trace): bool
    {
        return false;
    }
}
```

## view

引数が2つ。

- `User $user`
- `Trace $trace`

Laravelが自動的に`$user` => 現在ログイン中のユーザー、`$trace` => 操作対象のTraceを渡してくれる。

ログイン中ユーザーのidと対象Traceのidが一致するものしか操作することができない。

## PolicyのメソッドとCRUDの対応

```bash
viewAny     : 一覧を見る
view        : 1件を見る
create      : 作成する
update      : 更新する
delete      : 削除する
restore     : 復元する
forceDelete : 完全削除する
```
## Policyの呼び出し

Controllerなどから、

```php
<?php
$this->authorize('update', $trace);
```

のように呼び出す。

## まとめ

```bash
Controller
    │
    │ authorize('update', $trace)
    │
TracePolicy
    │
    │ update($user, $trace)
    │
$user->id === $trace->user_id
    │
    ├── true  -> 許可
    │
    └── false -> 拒否
```

Policyは誰が何をしていいのかという認可ルールをモデル単位でまとめる場所。
