# Nginx

## 概要

Webサーバーとして広く利用されているオープンソースのソフトウェア。

## Nginxの全体像

```bash
ブラウザ
    |
    | HTTP / HTTPS
    |
Nginx
    |
    | これは静的ファイルかな？
    | PHPかな?
    |
PHP-FPM
    |
Laravel
    |
Response
    |
Nginx
    |
ブラウザ
```

=> Nginxは外から来たHTTPリクエストを受け取って、適切な場所に振り分ける受付係みたいな存在。

## 設定ファイル

```bash
/etc/nginx/nginx.conf
```

### user www-data;

Nginxのworker processとどのLinuxユーザーとして動かすかを指定している。

Ubuntuではよく、`www-data`というユーザーが使用される。

=> Nginx -> www-dataというLinuxユーザーの権限で動作

### http {}

`http`ブロックは、HTTPサーバーとして動作するための設定が入っている場所。

=> `include`が超重要

```bash
http {
    include /etc/nginx/sites-enabled/*;
}
```

=> `/etc/nginx/sites-enabled/`にある設定ファイルを、この`http {}`の設定の一部として読込む

=>`nginx.conf`にすべての設定を書くわけではない

### /etc/nginx/sites-enabled/

```bash
ls -l /etc/nginx/sites-enabled/
default -> /etc/nginx/sites-available/default
```

=> 実際には、`sites-available/default`の内容がNginxに読込まれている

### なぜシンボリックリンクにするのか？

例えば今後、

```
sites-available/
├── default
├── tracenote
└── pawverse
```

と設定ファイルを用意したとする。このとき、

```
sites-enabled/
├── default -> ../sites-available/default
└── tracenote -> ../sites-available/tracenote
```

なら、

```bash
default:   # 有効
tracenote: # 有効
pawverse:  # 無効
```

という状態にできる。


- `sites-available`: 設定ファイルを置いておく場所
- `sites-enabled`: その中で実際に有効にするもの

=> 設定ファイル自体は削除せずに、リンクの有無で設定ファイルをコントロールすることができる

## server {}

`/etc/nginx/sites-available/default`に書かれていた。

```
server {
    listen 80 default_server;
    listen [::]:80 default_server;

    root /var/www/html;

    ...
}
```

### listen

```
listen 80 default_server;
listen [::]:80 default_server;
```

- listen 80: IPv4
- listen [::]:80: IPv6

`default_server`は、そのIPアドレス・ポートに来たリクエストを、どのserverブロックで処理するか決める際のデフォルトという意味。
