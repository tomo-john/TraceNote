# Service層

## 概要

なぜServiceに分離するのか？

## Dashboard

ルーティング:
```php
<?php
Route::middleware(['auth', 'verified'])->group(function () {
    Route::get('dashboard', DashboardController::class)->name('dashboard');
    ...
```

- ログイン必須
- DashboardController呼ぶ
- メソッド名は指定しないのは`__invoke`
- シングルアクションコントローラとして扱う

コントローラ:
```php
<?php
namespace App\Http\Controllers;

use Illuminate\Http\Request;
use App\Services\DashboardService;

class DashboardController extends Controller
{
    public function __invoke(DashboardService $service)
    {
        $user = auth()->user();

        $stats = $service->getStats($user);

        return view('dashboard', $stats);
    }
}
```

- 処理はServiceに移譲
- サービスから受け取ったデータをviewに渡すだけ

Dashboardで使用するデータ取得のロジックをコントローラから分離したかったため。

さらに、DashboardService内からGrowthServiceを呼び出している。

Growthに関する処理もDashboardServiceでやると責務が分かれるので分離。

## ServiceはLaravelの機能？

Serviceクラス自体はLaravelが強制しているものではなく、アプリケーション側で責務を整理するための設計上の考え。
