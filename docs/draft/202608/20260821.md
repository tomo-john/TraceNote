# TraceRelation振り返り

## 概要

基本から復習。

## HasMany

```php
<?php
public function outgoingRelations(): HasMany
{
    return $this->hasMany(TraceRelation::class, 'from_trace_id');
}
```

> このメソッドはTraceとTraceRelationの間にどんな関係があるとLaravelに教えている？

Trace(1) 対 TraceRelation(多)の1対多の関係だと教えている。

trace_relationsテーブルには`from_trace_id`と`to_trace_id`の2つのカラムがtrace_idを表し、

どちらのidかを指定しないとLaravelがわからないので、outgoingRelations()では`from_trace_id`を第二引数で指定している。

=> 取得するのは、TraceではなくTraceRelation

## belongsTo

```php
<?php
public function fromTrace(): BelongsTo
{
    return $this->belongsTo(Trace::class, 'from_trace_id');
}
```

> このメソッドは、どのモデルからどのモデルへの関係を定義している？

TraceモデルとTraceRelationモデルの関係。

> from_trace_idは何を表している？

trace_relationsテーブルのどちらのtracd_idを参照するかを指定している。

> $relation->fromTraceとしたとき、何が取得できる？

この関係がどこから始まっているTraceか。

## 第二引数

```php
<?php
$this->belongsTo(Trace::class, 'from_trace_id');
```

もし

```php
<?php
$this->belongsTo(Trace::class);
```

`trace_relations`テーブルのカラムにある、`from_trace_id`, `to_trace_id`のどちらのカラムで判断すればいいのかLaravelが判断できなくなる。

## 自己参照

2  |      10       |     30      |
